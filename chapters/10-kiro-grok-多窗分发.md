# 10. Grok Bot 总控 × Kiro 多窗分树（今晚沉淀）

> 适用：开发者通用 + 团队内部  
> 口误对照：**GOLC = Grok Bot**（总控助手），不是另一套产品。  
> 原则：**少绑死具体业务机密**；换项目只换路径/分支/部署命令，流程不变。

更新：2026-11-05（Asia/Shanghai）

---

## 10.1 角色怎么分

| 角色 | 干什么 | 不干什么 |
|------|--------|----------|
| **人（老板/主程）** | 拍红线、验收、**亲自把口令贴进正确的 Kiro 窗** | 不代写大段代码；不让总控碰剪贴板乱贴 |
| **Grok Bot（总控）** | 拆切片、写口令正文、标明「发给哪一窗」、盯回执、防撞车、监督进度 | **不直接往本机剪贴板塞内容**；不替人点 Kiro 发送 |
| **Kiro 窗（执行）** | Autopilot 改代码、commit、本地/云构建、五句话回执 | 不抢别的 worktree；不擅自上现网 |
| **产品 / 外联 Agent** | Brief、竞品、漏点清单、对客文案标准 | 不写 `permissions.yaml`、不进开发仓乱改 |

一句话：**Grok 分发与监督；人贴口令；Kiro 干活；产品定体验。**

---

## 10.2 多窗分树（一树一窗）

同一台电脑可开多个 Kiro 窗，但 **每个 worktree / 职责树只允许一个窗写**：

| 车道（示例名） | 典型目录 | 主责 | 禁止抢 |
|----------------|----------|------|--------|
| **pub** | `_kiro/pub` 或门户静态树 | 公开站 / 门户页面 | console Vue、后端 API |
| **console** | `_kiro/console` 或控制台 FE 独立树 | 登录壳、工作台、Keys/充值空态 | portal 页面、后端 |
| **api** | `_kiro/api` 或后端树 | API、错误引导、构建部署脚本 | 前端页面大改 |

双机时再加一条：**不同机器也按树分活**（例如 A 机 pub+console，B 机 api/供应）；空闲侧可只读验收或 staging 冒烟，**勿两人同写一树**。

合仓一律走 **PR**；现网支付开关 / 客户 Key 等红线项默认不动。

## 10.3 口令纪律（最重要，防贴错窗）

1. **总控在聊天里写清**：`发给哪一窗` + 口令正文（或「打开某 steering 文件全文粘贴」）。  
2. **人负责粘贴**：打开对应 Kiro 窗 → 粘贴 → 发送。  
3. **总控不碰剪贴板**：避免「以为贴到 A，实际剪贴板还是 B」把门户口令打进 API 窗。  
4. 贴之前看一眼窗口标题 / 分支 footer：`pub ≠ console ≠ api`。  
5. 已在 Working 的窗：短指令即可（例如「开」「继续切片2」），不必重复贴长文。

### 口令模板（8–15 分钟切片）

```text
【发给：<pub|console|api> 窗】
【切片名·8–15min】目录：<绝对路径> 分支：<branch>
做什么：<1–3 条，可验收>
验收：<curl / 页面 / build --check>
禁止：抢别的树；rsync --delete；对客露上游供应商名；未下令上现网
干完：五句话回执（做了啥 / 文件 / commit / 是否上线 / 下一片）
```

切片默认 **8–15 分钟**；超过 20 分钟就拆，别堆成「下午一大包」。

## 10.4 Kiro 本机配置（与第 2 节互补）

开干前固定动作：

1. **开对目录**（正确 worktree，不是备份枝）  
2. **Autopilot ON**  
3. **permissions.yaml 一次配好** → 各窗 Reload Window；弹窗点 **Always Allow**  
4. **一个任务一个对话**；会话 Internal error → 以 git 为准，新口令续跑，坏会话别空转超 2 次  

路径备忘（本机）：

```text
~/.kiro/workspace-roots/<hash>/permissions.yaml
```

`match` 全是字符串；禁止裸 `true`/`false`（会 fail-closed）。

## 10.5 部署与构建红线（可复用）

| 项 | 做法 |
|----|------|
| 静态同步 | `rsync -a`，**禁止 `--delete`**（除非任务写明全量替换） |
| 上线顺序 | **先 staging 验** → 人点头 → 再现网；一切片可回滚 |
| 本机弱时 | commit + draft PR，**临时云机构建**（够 RAM），产物打清晰标签；用完 **terminate**，防空转账单 |
| 现网小机 | 别在现网同机硬编大项目；migrate / 支付开关另审 |
| 对客文案 | **禁止暴露上游供应商名**（页面、docs、FAQ、控制台分组名、错误 `message`、邮件/公告都算）。只写自家品牌 + 模型名 |

「除了页面还有哪会漏」：定价/模型页、docs、FAQ、Keys 分组人话、错误文案、邮件、API 对客错误、客户能看见的 admin 界面——扫漏时整表过一遍。

## 10.6 总控怎么监督（进度话术）

人问「几个人在干活」时，总控应回报：

- **Working**：哪一窗、哪一切片、最近 commit  
- **待命**：树已开但还没贴口令  
- **阻塞**：等拍板（例如临时机构建要不要开）  
- **勿贴**：已交 PR / 已 Working 的窗不要重复长口令  

资源没打满时：优先 **补空窗**（例如 console 已开树未贴口令），再开新车道；同一树不开第二写窗。

---

## 10.7 与产品 Brief 怎么配合

- 产品 Agent 出 **全链路 Brief / 漏点清单**（登录→用量、空态矩阵、禁邮件主路径等）。  
- 总控把 Brief **钉仓路径 + 切片顺序** 写成 Kiro 口令。  
- Kiro 只改指定树；公开站窗与控制台窗 **错峰**，供应/API 另窗。  
- 验收人话示例：测试号走通「登录 → 知余额去充值 → Key → 一次调用 → 用量可见」。

---

## 10.8 新同事 15 分钟读完就能干

1. 读本手册第 1–3 节 + **本节 10**  
2. 拿到：仓库、自己的 worktree、staging 地址、红线列表（无密钥进聊天）  
3. 配 permissions → Autopilot → 等总控「发给你窗」的口令  
4. 干完五句话回执；等下一片，别自己跳窗抢活  

站群 / 非本业务项目：只换路径与部署命令；**多窗分树、人贴口令、切片、禁 --delete、staging 先验** 原样照搬。
