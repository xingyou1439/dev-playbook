## 0. 一句话目标

**快速 × 高质量 × 可并行**：把可自动化的全自动化；人只拍红线与验收。

---

## 1. 工作方式（默认）

| 原则 | 做法 |
|------|------|
| 小步快跑 | 交付按 **~10 分钟 / 最多 30 分钟** 切片，一切片一 commit，可合并可回滚 |
| 别按「周」排 | 用小时可见进度；禁止「下周再大包」 |
| 高并发 | 不同目录/不同职责开并行窗；**同一 worktree 勿两人改同一文件** |
| 资源拉满 | 本机改代码；编译/冒烟用云服务器；外联调研用产品/外联 Agent；额度与上游联调默认可用 |
| 少打断 | 权限一次配好；弹窗优先 **Always Allow**；别让人反复点 Allow |

## 2. IDE / Agent（以 Kiro 为例，可类比 Cursor）

### 2.1 开干前 checklist

1. **开对目录**：源码所在 worktree，不要在备份枝 / 空仓上改  
2. **Autopilot ON**：连续改文件少停顿  
3. **一个任务一个对话**：别用空 New Session 扯皮；插队用短口令  
4. **模式选用**  
   - 改已知小片 → 直接对话干  
   - 明确 Bug → Bug Fix  
   - 大新功能才 Spec/Plan（别凡事开 Spec）

### 2.2 减少点 Allow（关键）

允许列表在本机：

```text
~/.kiro/workspace-roots/<hash>/permissions.yaml
```

每个打开过的工程根目录对应一个 hash（看同目录 `.trust-migration.json` 里的 `root`）。

**写法要点：**

- 只支持已知 capability（常见：`shell`、`web_fetch`）  
- `match` **必须全是字符串**  
- **不要**写裸的 `true` / `false`（YAML 会当成布尔 → 权限文件加载失败 → fail-closed）  
- **不要**乱加未文档化的 `capability: file` 或裸 `"*"`（可能解析失败）  
- 把常用命令写成 `git *`、`python3 *`、`rsync *`、`curl *`、`aws *` … 一次性列全  

改完后：各窗 **Reload Window**（`Cmd+Shift+P` → `Reload Window`）。

弹窗仍出时：点 **Always Allow**（写入规则），不要只点一次性 Allow。

### 2.3 会话炸了怎么办

若出现 `Error sending prompt: Internal error`：

1. 看 git：有没有未提交改动 / 新 commit  
2. 没进 git 的进度当丢失 → **新口令续跑**，从「下一切片」写起  
3. 别在同一坏会话里空转重试超过 2 次

### 2.4 并行窗纪律

| 窗 | 职责 | 禁止 |
|----|------|------|
| A | 门户 / 前端静态 | 改后端 Go |
| B | API / 后端 | 改门户页面 |
| C | 调研 / 外联 | 直接改现网 |

同一路径只允许一个窗写；另一窗只读或收口。

## 3. Git / 部署通用纪律

1. **一切片一 commit**，信息写清切片名（S1a / S3a…）  
2. 现网静态资源：`rsync -a`，**禁止 `--delete`**（除非明确全量替换任务）  
3. 部署前：备份远端目录；部署后：curl / sha 验收  
4. 本机无编译器：commit + draft PR，**云机 / CI 编译冒烟**  
5. 密钥：本机密封目录 / Vault；**永不进 git、不进聊天明文**

---

## 4. 云服务器用法（资源拉满）

适合放到云上的：

- `go build` / 镜像构建 / 长测  
- 贴近现网的联调、冒烟  
- 大文件 rsync、日志只读排查  

本机负责：写代码、小切片、提交、指挥 Agent。

新同事：先拿到 AWS profile / SSH 方式 / 区域说明，再开干。

## 5. 多 Agent / 多人协作

| 角色 | 干什么 |
|------|--------|
| 主控（Grok Bot + 人） | Grok 写口令并标明发给哪窗；**人粘贴**；验收、权限、跨窗防撞（详[第10章](chapters/10-kiro-grok-多窗分发.md)） |
| IDE Agent（Kiro/Cursor） | 改代码、commit、部署脚本 |
| 产品外联 Agent | 竞品、外部 AI 工具、体验深扫（**不进开发权限文件**） |
| 供应链 / 运维 | 上游、云资源 |

交接口令模板（短）：

```text
【切片名·~10min】目录：<绝对路径> 分支：<branch>
做什么：<1–3 条>
验收：<curl/页面/测试>
禁止：<别动的目录或现网项>
干完：五句话回执（做了啥/文件/commit/是否上线/下一片）
```

## 6. 新电脑 / 新员工 30 分钟上手

1. 装 IDE（Kiro/Cursor）+ Git + 需要的语言工具（或约定「云上编」）  
2. 拉仓库；确认工作目录不是备份枝  
3. 复制本手册；配好 `permissions.yaml`（从老机器拷贝同 root 的文件）  
4. Autopilot ON；Reload Window  
5. 用「交接口令模板」跑一个 10 分钟切片练手  
6. 会用：Always Allow、云机冒烟、rsync 无 delete  

桌面放这份文件即可；仓库内可另存一份到内部 `docs/dev/`（自愿，非产品文档）。

## 7. 站群 / 非 AI 项目同样适用

换项目时只换：

- 仓库路径与分支策略  
- 云机与部署命令  
- 外联清单  

**不换**：切片节奏、权限一次配好、并行窗纪律、五句话回执。

## 8. 今晚已踩过的坑（备忘）

1. Autopilot 开了仍弹 Allow → 查 `permissions.yaml`，不是再开一次 Autopilot  
2. YAML 里裸 `true`/`false` → fail-closed「could not load permission settings」  
3. 口令贴错窗 → 看窗口标题/分支 footer，门户≠控制台≠API；**总控不碰剪贴板，人贴**  
4. 会话 Internal error → 以 git 为准续跑，别死磕坏会话  
5. 总控代贴剪贴板 → 易串窗；改为聊天写「发给 X 窗」+ 正文  
6. 对客文案漏上游名 → 页面/docs/FAQ/Keys 分组/错误 message/邮件整表扫

## 10. Grok Bot × Kiro 多窗分树（摘要）

完整版（推荐新同事精读）：[`chapters/10-kiro-grok-多窗分发.md`](chapters/10-kiro-grok-多窗分发.md)

**五条铁律（背下来）：**

1. **一树一窗**（pub / console / api 互不抢写）  
2. **口令由人粘贴**；Grok 只在聊天标明「发给哪一窗」+ 正文（GOLC=Grok）  
3. **切片 8–15 分钟**，一切片一 commit，可回滚  
4. **`rsync` 禁 `--delete`**；先 staging 验再现网；重构建用临时机、用完销毁  
5. **对客禁上游供应商名**（页面不止首页：docs/FAQ/Keys/错误/邮件都算）

交接口令模板见第 5 节；并行窗表见第 2.4 节与第 10 章完整版。
